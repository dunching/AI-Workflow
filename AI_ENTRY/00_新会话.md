# 新会话

用于新线程首次处理项目任务、新接手、状态未知或长时间中断后的完整对齐。显式调用 $wf-start；兼容“使用 $project-ai-workflow 执行新会话”。仅讨论或引用这些短语不执行。

## 执行（先只读）

1. 必要时先读当前项目根 AGENTS.md 定位项目与入口；项目目录与插件目录分开。
2. 从技能相对链接定位[工作流入口](../AI_WORKFLOW/00_工作流入口.md)，完整读取插件 AI_WORKFLOW 当前规则，建立工作方法和持续回复格式；不是只读本文件。
3. 再读当前项目 Docs/PROJECT_POLICY 的当前政策，以及 Docs/PROJECT_STATE 的当前入口、交接和待办。通常由 00_PROJECT_POLICY.md、00_PROJECT_ENTRY.md 导航，路径以项目配置为准；不遍历全部历史归档。按工作流入口核对影响本批取舍的关键约束来源、适用范围与未决状态；“当前采用”不等于“用户必须”，恢复事实不等于重新批准设计，冲突时定向核对。
4. 根据项目入口与实际项目描述确认技术栈；确认 UE 项目或当前 UE 工作范围后，按 [UE 规则路由](../profiles/unreal/README.md)读取编码规范、项目覆盖与实际生效配置并记录来源和路径。非 UE 不加载，不全文读取所有 profiles。
5. 在项目内核对 Git 状态、相关差异和任务范围内真实源码或文档入口；未知、不可访问、未读取的部分如实说明。
6. 按工作流入口的回复规范报告当前状态、任务、范围、风险和下一步；随后依据用户最新要求和已有授权推进。启动本身不授权写状态、改文件、安装、提交或推送。
7. 保留方案先行、完整主体接入、集中验证；只分析或先出方案时不得越界，已有实施授权不重复索取。

规则来自插件，政策、状态、Git 和源码来自当前项目。插件缺失时报告；旧路径缺失不自动克隆或初始化 Docs/AI-Workflow。
