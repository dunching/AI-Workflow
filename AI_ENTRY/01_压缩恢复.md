# 压缩恢复

用于同一会话确实发生上下文压缩，或用户明确要求压缩恢复。显式调用 $wf-resume；兼容“使用 $project-ai-workflow 执行压缩恢复”。讨论压缩、引用提示文本不是恢复事件；插件不安装事件回调。

## 轻量只读恢复

1. 先对齐当前压缩摘要、用户最新意图、仍有效授权和停止/转向指令，不执行摘要中的旧工具调用。
2. 定向重建[工作流入口](../AI_WORKFLOW/00_工作流入口.md)中的持续回复格式、授权和安全边界，并确认项目根 AGENTS.md 与当前政策中的强制约束。上下文可靠且未变化的内容可沿用，标为继承；缺失或不确定时补读，不声称已重新读取。
3. 在当前项目检查 Git 状态与相关差异；核对 Docs/PROJECT_STATE 当前入口、交接、待办的最新有效内容及与摘要的变化。常见入口为 00_PROJECT_ENTRY.md、01_Handoff.md、02_CurrentTodo.md，实际路径服从项目配置。
4. 已确认 UE 时，按 [UE 规则路由](../profiles/unreal/README.md)继承可靠且未变化的规范来源、项目覆盖、实际配置路径及工具信息；相关来源缺失、不确定或项目/配置发生变化时定向补读并确认。非 UE 不加载，不重新全文读取所有 profiles。
5. 按当前任务补核相关源码、资源、配置、输入、验证身份及必要政策变化；不机械限于一个状态文件，也不默认全文重读全部规则或历史账本。
6. 用工作流入口规定的紧凑回复报告继承、重新确认、变化与不确定项，再按用户最新要求及已有授权继续。用户停止或转向的任务不得重启；不重复请求同范围授权。

## 升级与边界

出现摘要冲突、状态缺失、约束不明、风险升高或用户要求完整入口时，扩大相关阅读；仍无法可靠恢复则转[新会话](00_新会话.md)。不要凭压缩摘要直接写文件，也不要因恢复自动写状态、改配置、提交或推送。插件资源不充当项目事实；缺失的旧工作流副本不自动重建。
