# 压缩恢复

用于同一会话收到自动压缩提示后恢复上下文。

## 使用方式

“使用 $project-ai-workflow 执行压缩恢复。”

由已加载技能定位本文件，不固定写项目副本或插件缓存的绝对路径。

## 最小只读确认

1. 从当前项目根 AGENTS.md 确认项目政策、状态文件位置及有效授权。
2. 在当前项目运行 git status --short 和 git diff --name-status，不在插件参考目录查询项目状态。
3. 读取当前交接和待办的最新摘要；默认是 Docs/PROJECT_STATE/01_Handoff.md 与 02_CurrentTodo.md，项目另有配置时使用实际位置。
4. 只核对当前任务相关的源码、资源、输入和验证身份；出现矛盾再读取相关状态或历史证据。
5. 区分继承内容、本轮重新确认内容和仍不确定内容，再按用户最后要求决定是否继续。

## 边界

- 不默认全文重读所有规则、历史账本或 Docs/README.md。
- 不凭压缩摘要直接修改文件，也不把插件自己的目录当作用户项目。
- 沿用已有明确授权，不凭摘要扩大范围，不因恢复重新请求相同授权。
- 用户已停止或转向的任务不能因为恢复而自动重启。
- 状态不确定、风险升高或用户要求完整入口时，改用插件内[新会话入口](00_新会话.md)。
- 项目没有 Docs/AI-Workflow 是插件模式的正常情况，不自动重新克隆或初始化该目录。
