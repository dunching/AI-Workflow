# 环境检查

## 何时使用

用户要求检查工具、准备构建或验证，或者环境问题阻断当前任务时使用。已有且未变化的环境结论可以复用，不因普通修改重新检查整台机器。

## 默认范围

- 默认只读：查询工具路径、版本、项目配置、注册引擎和必要资源是否存在。
- 不自行安装软件、改 PATH 或注册表、升级依赖、修改引擎或启动长时间构建。
- 任务已明确授权构建或测试时，环境核对通过后按原范围继续，不重复确认。

## 先确认项目环境

1. 从项目根 AGENTS.md、项目政策、项目文件和当前配置读取引擎根、工具路径与目标平台。
2. 核对项目文件、引擎构建入口和运行程序实际对应同一版本。
3. 用户指定的引擎不可用时报告实际缺口；不得静默换另一个引擎或混用其输出。
4. 只查相关配置与少量已知位置，不默认递归扫描磁盘。

## 按需检查工具

| 任务 | 检查内容 |
| --- | --- |
| 文档与文本维护 | UTF-8、相关路径、必要的版本控制状态 |
| Python / Node 脚本 | 所需运行时、依赖及实际入口 |
| UE 构建 | .uproject、引擎根、UBT / UHT、编译器、目标和平台 |
| UE LLT | 当前引擎的 TestTargetRules、TestModuleRules、LowLevelTestsRunner 和可复用测试目标 |
| 客户端、服务端或联网验证 | 匹配程序、资源、角色、端口、超时与运行条件 |
| 真实渲染和画面检查 | RHI、内容资源、截图能力及声明的渲染方式 |
| 视频或外部采集 | 用户要求或证据需要的录制工具、窗口隔离和输出位置 |

可用 Get-Command、版本查询、Test-Path 等进行定向检查。命令和路径以当前项目为准，不将某台机器的路径当成通用回退。

## UE 独立测试入口

- 独立算法、调度、值对象和编码等测试，先核对 UE LLT 路线。
- 不因没有现成 LLT 目标就默认搭建裸 C++ 程序和手工编译脚本。
- 必要时在已授权范围内做最小 LLT 接入；工具不可用时明确报告，不静默另建测试体系。
- 环境检查不等于已编译、已运行或已证明功能正确。

## 输出

只报告与当前任务相关的可用工具、实际路径和版本、缺失项及具体影响。
说明能够运行哪些验证、哪些尚不能运行，不枚举无关工具，不以环境检查替代功能实施。
