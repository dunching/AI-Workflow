# 功能验证与构建

## 适用时机

本流程用于已接通功能的集中验收、缺陷回归和明确要求的单功能检查。
主体实施期间的基础检查见[开发修改与维护规范](01_开发修改与维护规范.md)，不将本流程机械施加到每个局部改动。

## 验证批次

- 修改前确定本批要证明的行为、必要反例、受影响调用方和成本预算。
- 同一接口的生产实现、调用方、配置、编码恢复和必要测试夹具一次迁移。
- 主体接通后先做低成本检查，再集中构建和验证；不为每个文件、断言或可归并的诊断修正分别完整构建。
- 优先必要的目标或模块增量构建；反射、生成代码、模块依赖和资源变化做对应的 UHT / UBT 与运行验证。
- 同一有效构建可以运行多个测试集合，参数不同不自动要求重建。
- 只有新修改、新失败、覆盖缺口或明确要求才重复、扩大验证。
- 文档维护通常无需启动 UE；脚本和工具做与其实际行为相关的检查。

## UE 独立测试优先使用 LLT

- 独立纯逻辑、算法、调度、状态、序列化和协议测试，默认优先接入 UE Low-Level Tests（LLT）。
- LLT 用例仍然可以使用 C++；区别在于复用 UE 测试模块、构建规则、断言、筛选和报告，而不是自制另一套独立程序。
- 先复用现有 LLT 目标与夹具。新目标需要时，核对当前引擎的 TestTargetRules、TestModuleRules、LowLevelTestsRunner 与 TestHarness / Catch2 支持，做最小必要接入。
- 不默认新增类似 Tools/PerfTask/test_*.cpp 的裸 main() 测试、手工累计断言、直接调用 cl.exe / g++ / clang++ 的编译脚本或专用 runner。
- 确需验证完全脱离 UE 的可移植性或其他独立宿主时，在方案中单列必要性、维护成本和授权范围；不得仅因手写程序方便就替代 LLT。
- LLT 不可用时说明实际限制与候选方案，不静默搭建自制测试体系。
- 已有独立入口和历史证据保留；不自动删除，也不把全部迁移到 LLT 作为当前功能开发前置。
- Python 可以负责已有测试的调度和证据整理，不在外围脚本重写被测业务逻辑。

## 按证明范围选择层级

| 层级 | 证明内容 |
| --- | --- |
| 静态与语法检查 | 文档引用、脚本解析、受影响编译单元的基础接口 |
| UE LLT | 可隔离的生产纯逻辑、算法、调度和编码合同 |
| UHT / UBT 与链接 | 反射、模块、生成代码、目标编译和真实链接 |
| 原生或集成测试 | 实际 Worker、宿主、生命周期、恢复和共同提交 |
| 真实场景与渲染 | 内容资源、RHI、动画和实际表现消费者 |
| 客户端与服务端 | 实际网络角色、恢复接续、权威与副本 |
| 性能验收 | 固定负载、完整路径、有效窗口和匹配程序的实际指标 |

语法、LLT、链接和场景结果各有证明边界，不能互相替代。渲染验证见[可视化流程验证](05_可视化流程验证.md)。

## 构建和运行前一次核对

- 引擎根、项目、目标、配置、平台和实际程序身份匹配。
- 测试已注册，选择器命中真实叶级案例；需专用参数或捕获输入的案例单独识别。
- 初始状态合法，必要能力已安装；反例的拒绝发生在目标门，而非更早的无关前置。
- 输入、恢复资格、协议版本、目录、资源和恢复入口一致。
- 脚本支持所用参数，角色、端口、超时与资源占用符合本批需求。
- 依赖 RHI、渲染或内容的用例使用真实所需环境，不随意改成无渲染模式。
- 通过信号、预期失败、正向控制和证据位置明确。

检查结果仍有效时复用，不反复重做全部启动检查。

## 失败分类与集中修复

1. 输入、夹具或环境不满足：目标行为尚未验证；保留失败并修正前置。
2. 编译、生成代码或链接失败：后续运行尚未执行；按真实工具错误定位。
3. 进入目标行为后失败：区分生产缺陷和与已授权新语义冲突的旧预期。
4. 超时、崩溃、取消或未知原因：保留现场与已完成结果，不推定通过。

同一原因或接口的问题归并修复后集中复验。迁移旧预期时保留原报告和等价的安全、事务及生命周期要求。
不通过删除真实反例、放宽生产校验、改负载或改写参考输出取得通过。
需要修复前反例时集中取得真实失败证据，不为形式给每个小步骤单独制造一轮红绿。
反复验证未减少不确定性或主体没有推进时，使用[返工熔断与推进复盘](11_返工熔断与推进复盘.md)。

## 冻结、证据与结论

- 按项目要求在最终构建前完成格式化与检查，随后冻结受验证的源码、工具、配置、资源及输入。
- 验证期间不修改冻结内容。终态后修复时重开候选，并重新确认受影响的结论。
- 同一程序身份对应真实编译输入和引擎；不同版本的结果不混用。
- 保存原始命令、退出码、叶级结果、必要日志和输入输出，不重复扩建证据框架。
- 性能结论要求相同负载、有效目标窗口及项目规定的环境；短样本和诊断运行不能冒充稳定收益。
- 完成报告分别说明实现、正确性、性能和未覆盖事项。没有测量不编造耗时占比或节省承诺。
