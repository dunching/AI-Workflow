# 可视化流程验证

## 何时使用

用户要求检查实际流程、界面、游戏画面、动画、特效、内容资源或真实表现消费者时使用。
纯逻辑和非视觉功能优先使用[功能验证与构建](04_功能验证与构建.md)，不默认新增录屏工作。

## 以当前项目定义流程

- 从项目政策、当前任务、真实用户入口和源码确认要覆盖的流程。
- 本通用规则不预设地图、菜单、货币、商店、服务器阶段或业务玩法。
- 声明完整或局部覆盖，以及每个关键状态应出现的画面和实际行为。
- 若自动化从中途开始、绕过关键入口或没有达到声明状态，只能报告相应局部覆盖。

## 证据路径

- 遵守项目指定的证据方式；UE 项目优先复用真实客户端进程内的检查点截图。
- 截图、日志、权威检查、网络检查和性能数据分别证明各自范围，不用日志 PASS 代替画面。
- 动画、连续运动、轨迹、粒子和时序效果可用多个有意义时刻的截图，并按任务需要补充视频。
- 用户明确要求视频、窗口采集诊断，或进程内截图无法提供所需证据时，可用经说明的外部采集路径。
- 不为满足采集形式扩写无关工具；已有截图或录制入口优先复用。

## 真实输入与覆盖

- 用户路径可驱动时，优先通过真实可见控件、绑定按键或等价用户输入到达目标状态。
- 启动参数只用于配置已确认支持的角色、场景和运行条件。
- 调试命令、直接 RPC、强制状态和测试注入属于辅助路径；说明跳过了哪些用户步骤。
- 辅助路径不能被报告为全部真实用户路径覆盖；也不以鼠标输入替代实际权威和复制检查。

## 运行前检查

- 对应项目、程序、引擎、资源、角色和渲染后端匹配。
- 目标流程、通过信号、画面断言、输入路线、相机和采集方式明确。
- 每次运行隔离端口、RunId、日志、截图或视频目录和渲染尺寸。
- 使用哪些客户端或服务端、需要等待哪些状态，以及何时结束采集。
- 复用已授权的验证范围，不重复请求相同授权；额外外部操作遵循[工作流入口](00_工作流入口.md)。

## UE 截图

1. 从真实客户端的目标业务状态捕获命名检查点。
2. 记录检查点、文件路径与对应运行身份。
3. 等待截图落盘，实际查看图片或联系图后判断。
4. 拒绝黑屏、空白、旧帧、错误窗口、错误项目、尺寸错误和缺失检查点。
5. 最终检查点完成前不提前关闭客户端。

进程内截图可在当前平台及测试入口支持时使用 -RenderOffScreen，并明确尺寸。
真实窗口输入、外部窗口采集或人工观察需要可见窗口，不机械套用离屏参数。
不编造项目未支持的截图命令行开关。

## 相机与局部表现

- 默认用户视角不足以看清目标时，可以在授权范围内使用临时检查相机。
- 说明目标、距离、角度、视野和切换时机，结束后恢复或报告剩余相机状态。
- 局部检查相机证明目标细节；若要求用户可读性，还要检查正常视角。
- 临时相机、辅助脚本和调试路径不应形成第二套正式表现逻辑。

## 外部录制

- OBS、FFmpeg 或窗口采集需要真实可见窗口，先做最小采集确认，再运行长时间录制。
- 绑定目标客户端而非整个桌面；固定窗口位置和尺寸，避免遮挡、失焦及不同项目画面混入。
- 共享桌面的 OBS 有全局场景与录制状态，未隔离时不能让多个任务同时修改。
- 捕获连续过程和关键时刻，结束后检查视频或提取帧。
- 录制结束前保留目标客户端；优先正常停止录制和退出工具，不擅自强杀进程。
- 如使用桌面区域采集，明确区域与遮挡限制，不把错误窗口或桌面当项目证据。

## 分类与交付

| 分类 | 含义 |
| --- | --- |
| 完整视觉通过 | 声明流程和全部画面断言均实际覆盖 |
| 完整用户路径通过 | 关键步骤由真实用户输入或等价绑定路径完成且画面通过 |
| 局部视觉通过 | 只覆盖声明流程的一部分，列出缺口 |
| 业务画面失败 | 已到达状态，但必要画面或表现错误 |
| 采集失败 | 黑屏、旧帧、错误窗口、遮挡或缺失，业务结果未因此获证 |
| 仅日志通过 | 缺少足够视觉证据，不能称画面通过 |

报告实际检查过的图片、视频或帧位置，以及日志、运行身份、输入和相机路径。
按项目已有状态入口记录有意义的结果，不强制创建新的业务流程文档或套用其他项目的状态路径。
失败按原因集中处理，不因单个采集故障反复重跑全部业务流程。
