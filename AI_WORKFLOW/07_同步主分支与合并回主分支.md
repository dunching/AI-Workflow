# 同步主分支与合并回主分支

## 适用范围

用于用户明确要求从主分支同步、提交当前分支、推送并合回主分支的任务。
只同步、只提交或只推送的请求不自动授权整个流程；按实际授权选择阶段。
项目限制和[工作流入口](00_工作流入口.md)优先，不自动新建工作树。

## 确认状态与边界

- 当前分支、主分支、对应工作区、远端与上游必须真实存在并核对。
- 主分支名从项目或 Git 状态确认，不凭模板假设 main 或 develop。
- 说明待纳入的修改、两侧未提交内容、子模块及提交关系。
- 来源、目标、远端或未提交内容处置不明确时先澄清。
- 完整流程已获授权时正常步骤连续执行，不为每个 Git 命令重复确认。
- 不擅自追加无关修改，不默认强制推送、rebase、reset 或清理。

## 按授权执行阶段

1. 更新远端信息，核对主分支与上游关系。
2. 主分支可快进且工作区满足方案要求时，采用快进方式更新。
3. 将已更新主分支合入当前分支；默认合并，不擅自更换历史策略。
4. 审查实际差异，完成受影响范围内的必要检查。
5. 仅提交获授权的修改；用户已给消息或授权自行拟定时不重复询问措辞。
6. 推送当前分支到已确认的目标。
7. 在主分支工作区核对状态，再合入当前分支。
8. 检查合并新增影响，必要验证通过后推送主分支。

不能快进、出现未预期历史分歧、推送失败或授权范围变化时，停止相关后续阶段并说明。
不把某阶段失败理解为可以通过强制操作自动完成发布。

## 冲突与资源

按[合并工作树到当前分支](06_合并工作树到当前分支.md)保全并处理冲突。
二进制资产不伪造合并；保护其他用户改动、忽略资源和不可再生证据。
涉及运行程序或构建输入时遵守冻结要求，不在验证中修改对应源码。

## 结果

简要报告实际完成到哪一阶段、提交与分支、推送结果、相关验证、冲突和未完成事项。
不因单纯 Git 元数据变化启动完整 UE 构建；需要时按[功能验证与构建](04_功能验证与构建.md)选择检查。
