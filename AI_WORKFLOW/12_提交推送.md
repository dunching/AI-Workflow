# 提交推送

## 适用范围

用于当前仓库只提交、只推送或提交后推送。用户要求同步、合并或切换分支时按实际授权使用[分支同步与发布流程](07_同步主分支与合并回主分支.md)。按[工作流入口](00_工作流入口.md)继承已有授权和项目限制。

## 核对提交和推送边界

1. 在目标仓库核对 Git 根目录、当前分支和 `git status --short --branch`。分别检查工作区与暂存区差异、未跟踪文件、子模块和 Git 进行中的合并、变基或其他操作。分支游离、存在冲突或操作状态与本次目的不符时先解决归属或状态问题。
2. 确认用户授权的文件、同一文件中属于本次的改动及已有暂存。用户说“提交本轮改动”时按当前任务归属选择；明确要求全部时按所指工作区检查所有候选。核对敏感配置、生成物、大文件、运行证据及子模块指针是否应入库。已暂存内容的归属以差异和任务证据为准。
3. 简要说明拟纳入内容、验证及适用的推送目标。范围清楚且已有授权时继续。只为影响结果的混合改动、未授权的待推提交或目标歧义澄清。

## 提交

- 先完成项目要求的相关验证，复用与候选内容匹配的有效结果。检查实际提交候选的 diff 与空白错误；必要时按 [集中验证](04_功能验证与构建.md)补足受影响范围。用户明确要求保存未通过的检查点时，如实记录结果。
- 暂存明确的文件或变更块。完整索引只包含授权内容时，审查 `git diff --cached` 后正常提交。已有无关暂存且本次选中文件可整文件提交时，可对已纳入索引的路径使用 `git --literal-pathspecs commit --only -- <路径...>`。该方式读取选中路径的**工作区**内容，必须先核对与 HEAD 的完整差异。选中路径含须保留的部分暂存或混合改动时，按变更块隔离；无法安全隔离时先澄清，保留原暂存。处理移动时核对源与目标两端。
- 紧邻提交前复核所选差异，避免并发改动被带入。按用户给定或项目惯例拟定提交消息，保留项目钩子与签名要求。没有选中的改动时跳过空提交，仍按授权判断是否有现有提交待推。
- 提交后核对新提交的 ID、实际差异与剩余暂存/未暂存内容。提交失败时保留现场，按错误处理后复核候选；核对当前 HEAD 后再决定是否重试。

## 推送

1. 核对当前分支上游或用户指定的远端和目标分支，并检查实际推送地址。读取实际目标的最新引用，检查共同历史、领先/落后和从该目标到拟推提交的**全部**新增提交。只推送也执行此检查。新远端分支须符合用户意图和项目分支政策，并核对将被引入的历史；推送目标存在歧义时澄清。
2. 只推送授权的目标引用和确认过的提交。目标已含全部拟推提交时，报告已同步。目标领先或分叉时，按实际状态报告并遵循已有同步授权；提交推送入口本身只做普通推送。涉及子模块指针时确认远端可取到引用提交；子模块的提交、推送各自按授权执行。
3. 使用明确的目标引用进行普通推送，防止 Git 默认配置扩大范围。可用 `git push --porcelain --no-follow-tags --recurse-submodules=check <远端> <提交ID>:refs/heads/<目标分支>`，分支需建立跟踪关系时按用户意图和项目约定设置。启用镜像推送或有多个推送地址时，先确认实际影响范围。
4. 推送后向实际目标核对远端引用。目标恰好指向拟推提交，或经验证已包含它，才报告提交已到达。遇到钩子、权限、保护分支或非快进拒绝时保留已完成的本地提交及真实错误；按获授权方式解决，保留已有历史和远端保护。

报告本地提交 ID、涉及的分支、实际推送目标与远端核对结果，简述验证、剩余改动和失败所在阶段。
