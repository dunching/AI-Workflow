# 收敛清理与整理重构

## 确定范围和保护对象

- 从用户指定的任务、模块或目录进入。结合项目入口、`git status --short --branch`、差异和 Git 归属识别已有改动、候选对象及需要保全的内容。只做审查或只出方案时，交付候选、引用证据和建议顺序。
- 从真实调用者、资源和配置入口追到消费者，核对拟保留的业务行为、公开接口、存档、协议及兼容期。按项目实际情况查找反射、序列化、注册表、构建、打包和资产引用；仅凭文本搜索没有命中，无法判定动态入口或资产可删。整体设计收敛沿用[架构审查](10_架构质询与设计审查.md)的范围和完成标准。
- 对每类实际候选说明整理方式及依据：可以合并的重复职责、已无有效消费者的旧路径、可安全再生的本地产物，以及可归并的项目状态。保全用户未提交改动、当前有效程序与资源、原始失败及不可再生证据。Git 忽略状态只说明版本控制处理方式。

## 按授权收口

1. 先给出简要方案，说明清理对象、影响、保留的合同、迁移顺序及验证方式。明确的整理实施请求覆盖范围内有证据、可恢复的内部调整；涉及范围扩大、删除不可再生内容、改变外部合同或架构实质转向时，按[工作流入口](00_工作流入口.md)处理授权。
2. 优先删除无用职责、合并重复逻辑、缩窄依赖或整理文件归属。沿正式入口迁移调用方、测试、配置、引用和必要的兼容路径，再退役旧实现。行为保持按正式调用路径验证；确需变更的外部行为按授权迁移。
3. 移动或删除本地文件前，核对最终解析路径、Git 归属、引用、当前占用及恢复方式。对工作区外路径、目录联接或符号链接核对真实落点。只处理确认归属和用途的具体路径，递归操作须逐个核对目标在授权目录内。现有工作树整合按[工作树合并流程](06_合并工作树到当前分支.md)保全，移除工作树另按实际授权处理。
4. 有项目状态收口需求时，按现有入口更新当前交接、待办和证据索引。只关闭已有证据支持的事项，保留未验收项和原始结果。整理任务的提交或推送按[提交推送流程](12_提交推送.md)取得相应操作授权。

## 集中验证和交付

- 核对最终 Git 差异、引用及正式入口，确认预期清理对象已经移除或归并。按[集中验证](04_功能验证与构建.md)验证受影响的行为、恢复或加载路径，并按需构建或检查打包。清理生成物时检查必要的再生入口；已有匹配证据可复用。
- 报告实际删除、移动或合并的内容、行为保持的证据、仍需保留的旧路径、未验证项及待决事项。仅完成局部清理时明确实际覆盖范围。
