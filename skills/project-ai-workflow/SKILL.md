# 项目开发工作流

## 项目与插件目录分开

- 当前任务的工作目录、项目根 AGENTS.md、项目政策和状态文件属于用户项目；项目 Git 操作与源码定位都在该项目中进行。
- 本技能所在目录只用于定位随插件发布的规则。通过本 SKILL.md 的相对链接读取参考文件，不猜测固定缓存路径、盘符或版本目录。
- 项目使用插件模式时，不要求存在 Docs/AI-Workflow，不自动克隆、初始化或恢复该目录。
- 用户当前明确要求和已有授权优先；技能不自动授权提交、推送、创建工作树、外部写入或扩大任务范围。
- 插件未加载或技能不可见时，明确报告，提示加载插件；不伪造已读规则或静默换用旧项目副本。

## 会话入口

保留本技能兼容；短入口分别为 $wf-start、$wf-resume、$wf-status、$wf-check。只在实际要求对应动作时执行，引用或讨论触发短语不执行。所有项目相关回复持续遵循[工作流入口的回复规范](../../AI_WORKFLOW/00_工作流入口.md)，不只在首次回复使用。

用户指定以下模式，或当前会话确实收到相应恢复指令时，只选择对应会话入口，再按该入口读取必要规则和项目文件；不并行重跑其他入口。

| 模式 | 插件内入口 |
| --- | --- |
| 新会话 | [新会话](../../AI_ENTRY/00_新会话.md) |
| 压缩恢复 | [压缩恢复](../../AI_ENTRY/01_压缩恢复.md) |
| 状态恢复 | [状态恢复](../../AI_ENTRY/02_状态恢复.md) |
| 修改前确认 | [修改前确认](../../AI_ENTRY/03_修改前确认.md) |

调用示例：“使用 $project-ai-workflow 执行压缩恢复”。
这是 Agent 的工作指令，不自行注册压缩事件回调或后台脚本。项目入口中的触发提示负责选择模式；规则文件由本技能定位。
已切换插件模式后，收到旧文件名形式的恢复提示时，说明映射到上述插件入口，不因旧项目路径缺失重新拉取工作流。
恢复只读取当前项目的事实，优先当前摘要和相关差异，不全文回读历史账本，不凭恢复动作重启用户已停止的任务。

## 按需使用规则

共享方法从[工作流入口](../../AI_WORKFLOW/00_工作流入口.md)开始；规则正文只维护 AI_WORKFLOW 这一份。
当前项目明确指定其他有效工作流时遵守其实际入口，发生冲突时报告，不把插件参考目录当项目状态。关键约束来源、方案有效期及内部简化边界统一按[工作流入口](../../AI_WORKFLOW/00_工作流入口.md#约束来源与方案有效期)执行，恢复摘要不升级实现选择的权威。

- 开发与架构修改：按[开发修改与维护规范](../../AI_WORKFLOW/01_开发修改与维护规范.md)先给方案，连续完成主体框架与生产接入，再集中验证修复。
- 缺陷或文档与代码冲突：按需用[源码分析](../../AI_WORKFLOW/03_文档业务与源码分析.md)确认因果和相关调用链。
- 构建与回归：用[功能验证与构建](../../AI_WORKFLOW/04_功能验证与构建.md)；UE 独立测试优先 LLT，不默认新增裸 main()、手工断言和编译脚本。
- 工具前置、视觉证据或反复返工：分别用[环境检查](../../AI_WORKFLOW/02_环境检查.md)、[可视化验证](../../AI_WORKFLOW/05_可视化流程验证.md)、[推进复盘](../../AI_WORKFLOW/11_返工熔断与推进复盘.md)。
- 仅确有需要时使用[产品对齐](../../AI_WORKFLOW/08_产品目标与价值对齐.md)、[技术调研](../../AI_WORKFLOW/09_技术调研与限时验证.md)、[架构审查](../../AI_WORKFLOW/10_架构质询与设计审查.md)。
- [工作树合并](../../AI_WORKFLOW/06_合并工作树到当前分支.md)和[同步发布](../../AI_WORKFLOW/07_同步主分支与合并回主分支.md)只用于用户授权的相应操作。

## 执行和报告

新会话按对应入口完整读取 AI_WORKFLOW 当前规则；压缩恢复与日常任务只补读必要参考。不把技能模板变成逐条测试红绿、逐项提交或反复审批。
同一接口的生产调用方、版本、恢复与必要夹具一起迁移，完整批次后集中审查验证。
复用有效检查，按[功能验证与构建](../../AI_WORKFLOW/04_功能验证与构建.md)区分探索性验证和正式验收；正式验收按要求冻结输入，保留真实失败证据。报告实际功能、证据、阻断和剩余交付，区分主体实现、正确性和性能。
