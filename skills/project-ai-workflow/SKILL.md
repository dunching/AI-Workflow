# 项目开发工作流

## 入口与事实源

先按当前项目根 AGENTS.md 定位项目政策和当前任务。用户最新明确要求及已有授权优先于技能默认模板；本技能不自动授权提交、推送、工作树、外部写入或扩大范围。

共享规则入口为[工作流入口](../../AI_WORKFLOW/00_工作流入口.md)。参考文件随插件打包，全部使用插件内相对路径；规则正文只维护 AI_WORKFLOW 这一份，不依赖开发机器的绝对路径。修改共享规则仍需用户授权。
当前项目明确指定其他工作流位置时，使用该项目实际入口，不把本技能的共享目录当成项目状态。

## 按需读取

- 开发、架构改造或日常修改：读取[开发修改与维护规范](../../AI_WORKFLOW/01_开发修改与维护规范.md)。先厘清方案，连续完成完整功能主体和生产接入，再集中验证修复；实施期间保留必要基础检查。
- 缺陷或文档与代码冲突：按需读取[源码分析](../../AI_WORKFLOW/03_文档业务与源码分析.md)，确认因果和相关调用链，归并同因修复。
- 构建、独立测试与回归：读取[功能验证与构建](../../AI_WORKFLOW/04_功能验证与构建.md)。UE 独立测试优先 LLT，不默认新增裸 main()、手工断言和编译脚本。
- 工具或运行前置确有问题：读取[环境检查](../../AI_WORKFLOW/02_环境检查.md)。
- 画面、动画或用户路径需要证据：读取[可视化流程验证](../../AI_WORKFLOW/05_可视化流程验证.md)。
- 反复失败、超过预算或主体长期没有进展：读取[返工熔断与推进复盘](../../AI_WORKFLOW/11_返工熔断与推进复盘.md)。

不默认加载全部参考。仅在任务确有需要时使用[产品对齐](../../AI_WORKFLOW/08_产品目标与价值对齐.md)、[技术调研](../../AI_WORKFLOW/09_技术调研与限时验证.md)和[架构审查](../../AI_WORKFLOW/10_架构质询与设计审查.md)；已确定路线不反复重新选型。
[工作树合并](../../AI_WORKFLOW/06_合并工作树到当前分支.md)和[分支同步发布](../../AI_WORKFLOW/07_同步主分支与合并回主分支.md)只在用户授权相应操作时适用。

## 执行与报告

- 用户只要求分析、方案或调整方法时，只交付该项内容；用户已授权实施时在相应范围内继续，不重复确认。
- 不将计划拆成逐条测试红绿、逐项提交和反复审批，也不把测试设施重建作为主体实施前置。
- 同一接口的生产调用方、版本、恢复与必要夹具一起迁移；完整批次后集中审查和验证。
- 复用仍有效的检查；按项目要求冻结验证输入，保留失败证据，不混用不同程序或源码身份。
- 进度报告实际功能、证据、阻断和剩余交付；分别说明主体实现、正确性和性能，不用测试数量或文件数量制造完成率。
- 压缩恢复按[轻量恢复入口](../../AI_ENTRY/01_压缩恢复.md)补读当前状态和相关差异，存在矛盾再扩大阅读；用户要求停止旧计划时按[状态恢复](../../AI_ENTRY/02_状态恢复.md)保持只读。
